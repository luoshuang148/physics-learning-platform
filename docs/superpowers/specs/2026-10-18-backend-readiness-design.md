# Backend internship readiness design

Accepted scope: implement the preceding code review recommendations, upload the unchanged project to GitHub first, use a readable English repository name, and commit every major change.

Decisions made by the implementer: repository physics-learning-platform is private by default; retain the original package names and license. Work in the newly initialized checkout on a feature branch after the baseline push. Keep Spring MVC/JPA and avoid introducing Redis, MQ or microservices.

1. Registration: public registration accepts STUDENT only, including direct HTTP calls. Teachers promote existing students through the existing protected user administration flow. Remove the client-side teacher secret and explain provisioning.
2. Sessions: include user ID in cache keys, scope persistent history queries/deletes to the authenticated user, remove expired/inactive entries without test-only timestamp manipulation, restore ordered historical context after cache eviction/restart. Bound cached sessions and preserve token accounting. Session IDs remain client-correlated identifiers, never authorization.
3. Streaming: each emitter has independent cancellation, cancellation hooks cancel the actual OkHttp Call even while blocked; at most one generation may bind to a given conversation at a time. Completion releases ownership. Bounded executor uses explicit rejection rather than CallerRuns; every rejected or failed request closes its emitter. Add per-user connection admission. Keep synchronous upstream I/O on dedicated bounded workers and describe it accurately.
4. Queries: add database-paged teacher record search (page >= 1, size 1..100), stable answeredAt/id order, correct/wrong and student-name filters on the server. DTO projection excludes image bodies; existing clients remain compatible while teacher UI moves to pages. Replace legacy per-record question lookups with a batch query. Measure SQL counts against cold persistence contexts.
5. Events: ending the current event archives it and preserves all learning data. Associate new answers, conversations and reports with an optional eventId; existing data remains legacy/unassigned. An active singleton slot with a unique constraint enforces a single current task, with null slots allowing archived history. Add a history endpoint and update UI copy; supply a non-destructive SQL upgrade script. No production database is altered automatically.
6. Delivery: Maven Wrapper, JDK 21 setup, portable dev profile, CI for backend/frontend and MySQL 8.4 integration tests, reproducible query benchmark instructions. Real API keys are never required in default tests. Do not claim real-model load capacity or production deployment without evidence.
7. Documentation: correct SDK/LRU/nonblocking/token-refresh claims, concise README with quickstart, architecture, provisioning, archive behavior, verification and honest resume bullets. Preserve attribution for bundled simulations.

Success: independent commits per item, targeted regression tests fail before each fix and pass afterward, complete default suite and frontend build pass, MySQL CI checked when available, GitHub holds baseline and all final commits.
