# 知识库后端阶段记录（T2）

状态：上传、版本登记、班级授权、撤回与原文读取接口已实现；索引任务和学生端引用交互仍在后续任务中。功能默认关闭。

## 接口

- POST /api/v1/knowledge/documents：教师 multipart 上传 file/classId/title，返回202及文档/版本状态。
- GET /api/v1/knowledge/documents：班级教师分页查看，size最大50。
- POST /api/v1/knowledge/documents/{id}/reindex：登记新版本；UPLOADED/INDEXING状态重复请求复用同一待处理版本。
- DELETE /api/v1/knowledge/documents/{id}：先撤回访问资格，返回204；文件/向量后台清理待T4接入。
- GET /api/v1/knowledge/chunks/{id}：只返回有班级权限且READY版本的片段；不返回原始文件路径或存储key。

功能未启用时返回明确的业务错误；T2本身不会执行Embedding或调用模型，也不会把UPLOADED直接写成READY。旧AI端点和前端行为保持。

## 数据边界

学生只读所属班级，教师只管理有关联的班级，未加入班级不会隐式分配默认班级。每次读取均验证当前账号激活状态、班级状态和成员关系。撤回资料和取消成员关系后原文不能继续读。

上传只支持.md/.txt/.pdf；10MiB上限同时校验声明大小与实际读取量；文本要求有效UTF-8，PDF检查魔数。PDF内容解析、扫描件识别、页码与切分由T3完成，不能把T2魔数检查称为完整PDF验证。

资料使用服务端随机文件key和内容哈希，前端只获得DTO。班级配额检查持有班级数据库锁；文件写入后的数据库失败/事务回滚会尝试清理新文件。知识库目录纳入git忽略。

owner_id是不可变创建者审计ID，不作为读取权限，也不新增阻止原账号删除流程的外键。班级、版本和片段关系由数据库外键约束；历史资料访问仍由当前权限决定。
