# 后端实习简历与面试准备

## 定位

项目名：Physics Learning Platform（物理教学学习平台）。适合突出 Java 后端工程实践：访问控制、持久化查询、异步流式资源管理和数据保留。不要声称独立从零实现全部原有功能；应明确自己的改进范围，并能对应 Git commit 解释。

## 可选的简历内容

技术栈：Java 21、Spring Boot、Spring Data JPA、MySQL、JWT、OkHttp、SSE、JUnit、GitHub Actions。

> 基于 Spring Boot 开发与完善物理教学平台后端，支持学生答题、教师任务管理和 AI 流式辅导；完善学生注册及教师操作权限，按用户与任务隔离 AI 会话，支持持久化恢复、过期回收和缓存容量限制。
>
> 针对教师答题记录查询的 N+1 问题引入关联预取，并通过 DTO 投影实现有界分页和服务端筛选；在冷持久化上下文、25 道不同题目回归场景中，将旧列表 SQL 数量从 27 条降至 2 条。
>
> 设计请求级 SSE 取消与上游 OkHttp 调用联动，处理同会话重复请求、连接限额及有界执行队列拒绝；将教学任务删除改为归档，通过 MySQL 生成列唯一索引限制活动任务，保留历史学习数据并提供增量升级脚本。
>
> 使用 Maven Wrapper 和 GitHub Actions 建立后端回归、前端构建及 MySQL 新建/升级验证流程，提高项目复现与交付能力。

本轮可替换其中一项：

> 设计任务题目快照和基于用户/请求键的幂等作答，使用事务锁和唯一约束处理重试、归档与旧页面替换冲突；分离首次成绩与补练掌握度，通过数据库聚合支持任务统计，并建立浏览器全流程及 MySQL 迁移、备份恢复验证。

一页简历选其中 2–3 点即可。SQL 数值必须带场景；不要写“高并发”“分布式”“百万用户”“性能提升 XX%”或把测试数量当覆盖率。CI 实际通过后再写“通过 CI 验证”。

## 面试需要讲清的内容

| 问题 | 可以结合代码说明 |
| --- | --- |
| 为什么前端限制教师注册不够？ | 请求可以绕过页面，所以服务端注册持久化前拒绝非学生角色；教师由运营或受保护接口创建。 |
| sessionId 为什么不能单独作为 key？ | 同名 ID 可由不同用户提交；缓存及数据库查询必须包含 userId，任务切换还需要 eventId。 |
| SSE 断开为什么要取消上游？ | 单纯检查布尔标记无法打断阻塞读；注册取消 hook 后，`Call.cancel()` 能中止上游连接。 |
| 为什么还要限制队列？ | 连接限额与执行队列是不同资源；拒绝时也必须关闭 emitter、释放用户与全局计数。 |
| 怎样确认 N+1？ | 制造每条记录不同题目的夹具、清空持久化上下文、统计真实 SQL，避免缓存造成假象。 |
| 为什么数据库保证活动任务唯一？ | “先查再插”存在并发窗口；生成可空槽位配唯一索引，活动行槽位为 1，历史行为 NULL。 |
| 归档后数据如何关联？ | 新答题、对话和报告记录 eventId；旧数据无法可靠反推，因此保留空关联。 |
| 现在能横向扩容吗？ | 单机缓存与连接计数无法跨实例协调，还需共享限流、会话路由和取消策略。 |
| 测试覆盖有什么不足？ | H2 不完全等同 MySQL，另设真实 MySQL 表结构测试；没有生产压力或真实模型吞吐证明。 |

## 展示建议

准备一个自建教师与两个学生，演示注册权限、发布任务、答题、分页筛选、归档与历史仍存在。再展示 SQL 回归测试、阻塞上游取消测试、MySQL 迁移及相关 commit。演示 AI 时使用自己的有效密钥；离线演示可关闭 AI 并解释资源测试使用本地模拟上游。

本轮进一步实现任务不可变快照、预期 ID 原子替换、并发幂等提交、原始成绩与补练分离、JWT 撤销、有界会话恢复，以及浏览器生命周期、MySQL 迁移和备份恢复验证。可用这些具体失败场景及 commit 说明设计取舍。

可继续研究的边界是深分页、多实例协调和真实模型教学质量。能说明这些边界，比堆砌未经实现的技术名词更有说服力。
