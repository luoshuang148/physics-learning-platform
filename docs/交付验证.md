# 交付验证与复现

范围是单学校多班级、单应用实例（Redis 与 MySQL 独立部署）。所有夹具均为合成数据，AI 关闭；浏览器安全测试只在浏览器内模拟 SSE，不连接模型、不计费。不要把以下测试脚本指向业务库。

## 回归与浏览器主流程

```bash
./mvnw -B test
cd frontend
npm ci
npm test
npm run build
npx playwright install chromium
# 先启动独立 MySQL（空库即可，Flyway 自动建表），再启动对应版本后端与前端
E2E_ALLOW_WRITES=1 E2E_BASE_URL=http://127.0.0.1:18080/api/v1/ npm run test:e2e
```

会写数据的浏览器测试还要求 `E2E_ALLOW_WRITES=1` 和 loopback 地址；仅在可销毁的隔离库中设置。各流程定位自己创建的任务，不清理其他任务。模拟接口测试不需要这个开关。

浏览器测试使用 `E2E_TEACHER_USERNAME/E2E_TEACHER_PASSWORD`（默认仅为测试夹具），由显式教师初始化创建；它注册独立学生，生成题目，在教师页面选题发布，在学生页面作答，归档后修改题库并重用题目，验证新任务未完成、空任务报告不读旧数据、历史快照补练及首次成绩不变。另模拟恶意 AI HTML，验证净化和作答记录 ID。失败时保留截图与 trace，成功时保存流程截图。

点击“提交答案”后由服务端判分并直接持久化。网络发送前持久化完整请求，失败重试复用同一请求；响应丢失后刷新会与服务器记录核对。缓存按用户、任务与首次作答/补练隔离，只恢复草稿，完成情况以服务器为准。浏览器另有两条回归覆盖这些路径。未收到服务端成功确认不计为完成。

CI `delivery` 作业实际构建 Dockerfile 的多阶段镜像，使用生产 profile、独立 MySQL 8.4、关闭 AI，先等待健康检查，再跑上述流程。检查对应提交的绿色状态和 `delivery-evidence` artifact；本地 Jar 与外部静态目录的验证不能代替镜像启动验证。

## 数据升级与备份恢复

MySQL 专项 JUnit 在隔离库分别验证 Flyway 空库迁移和 V1→V7 旧库升级后的 baseline。`scripts/verification/mysql_delivery.py upgrade` 会销毁测试库，加载 V1 夹具并生成 MIGRATED/MISSING 旧题和原始记录，验证重复 QIDS 按首次位置去重、格式损坏描述保留但不猜测题目，以及非破坏升级、令牌撤销和保留的尝试顺序，然后清空夹具供 JUnit 复用。

```bash
# 仅独立容器，MYSQL_PWD 使用该测试容器的密码
CONFIRM_ISOLATED_DATABASE=1 MYSQL_CONTAINER=your_test_container MYSQL_PWD=your_test_password \
  python3 scripts/verification/mysql_delivery.py upgrade
```

`backup` 阶段使用一致性转储，恢复到独立的 `physics_restore_check` 库，对每张表比较行数和内容 CHECKSUM，验证通过后删除恢复库与临时转储。它不会从主测试库删除数据；恢复库名也不能被业务使用。运行前停止测试写入。

```bash
CONFIRM_ISOLATED_DATABASE=1 MYSQL_CONTAINER=your_test_container MYSQL_PWD=your_test_password \
  python3 scripts/verification/mysql_delivery.py backup
```

本地非容器 MySQL 可改用 `MYSQL_SOCKET=/absolute/path/test.sock` 和 `MYSQL_BIN_DIR=/absolute/path/bin/`，必须确认该 socket 属于可销毁的实例。用户名可用 `MYSQL_USER` 覆盖，密码通过 `MYSQL_PWD` 传递，不写进源码。普通生产备份还应包括视频卷、配置密钥的安全保管、异机副本与恢复演练；测试的临时备份不等于生产备份策略。

## HTTP 实测

`http_benchmark.py` 仅接受 loopback 地址和显式隔离确认。脚本在测试库生成 100 个学生、50 道题、5000 条原始作答，每条作答带 1KB 合成图片快照，预热后交替请求教师分页与任务统计。默认 400 次请求、并发 8，输出成功数、QPS、P50/P95/P99、响应字节数、数据规模及机器/数据库信息。只测这两个读取入口；不测真实模型、不模拟全部线上业务。

```bash
CONFIRM_ISOLATED_DATABASE=1 MYSQL_SOCKET=/absolute/path/test.sock MYSQL_BIN_DIR=/absolute/path/bin/ \
  python3 scripts/verification/http_benchmark.py > benchmark.json
```

CI 同样运行并上传原始 JSON。不同机器与缓存状态不可直接比较，不把本地吞吐量写成生产容量或优化百分比。具体索引对比见[性能验证](性能验证.md)。最终修复版本另有 [HTTP 结果](verification/2026-10-18-final-http.json) 和 [备份恢复结果](verification/2026-10-18-final-backup.json)，作为交付复核，不与前一轮缓存状态不同的样本计算提升比例。

## 运行指标与 AI 质量

`GET /api/v1/actuator/health` 公开且不含内部细节；`/actuator/metrics` 必须携带当前教师令牌。可查看 `ai.sse.active`、`ai.executor.active`、`ai.executor.queue`；调用模型后出现 `ai.upstream.duration`（provider/outcome）和 `ai.upstream.first.content`。普通 HTTP/JVM/连接池指标由 Actuator 提供。生产监控采集账号应使用专门的教师凭证并安全保存，不能公开令牌。

固定教学评测样例和评分流程见 [AI 评测](ai-evaluation/README.md)。确定性回归验证输入、快照、统计、匿名化及资源边界；另已采集十条真实模型输出，仍待两名教师评分，尚无准确率结论。

## 报告与时间契约

教师未传任务 ID 时只分析当前活动任务；没有作答时直接返回无数据，不调用模型。报告输入先计数，最多 5000 条，按批次读取文字投影，不读取完整 JSON 或图片正文；单字段最多 4096 字符，总输入及最终提示词最多 128 KiB UTF-8，超限明确拒绝。快照存在时包含空解析在内都使用保存的版本，不能用后来编辑的题库填空。旧记录没有可恢复快照时标记题库回退；完整快照缺少文字索引时要求核对修复，不偷偷改读新题。每次成功生成保留独立报告版本，最新报告按更新时间及 ID 确定，允许同一范围并发生成。

新增作答及任务时间输出带 `Z` 的 UTC 时间，由浏览器转换本地时区；升级前时间保留无偏移格式并标记 `LEGACY_LOCAL`，不猜测原始时区。

- 已保存复盘按输入作答版本恢复，补练使缓存失效：`StudentTaskResultTest`、`assignment-review.spec.ts`。
