# 部署与数据库升级

## Docker 单机部署

复制 `.env.prod.example` 为 `.env`，填写数据库密码、随机 JWT 密钥、实际来源地址、模型密钥；首次教师按本地启动指南设置。执行：

```bash
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail=100 app
```

Compose 使用 MySQL 8.4、Java 21 和 Node 22 构建，前端打包进后端静态目录；首次启动由应用内 Flyway 自动建表，访问 `http://服务器地址/api/v1/`。宿主机 `/data/mysql` 保存数据库，`/data/videos` 保存视频；启动前确认目录权限与磁盘空间。数据库端口只绑定本机。AI 可设置 `AI_ENABLED=false` 进行无模型演示。

首次成功启动教师账号后，关闭初始化、删除明文密码并重新创建 app 容器。配置 HTTPS、备份及真实监控后再用于外部用户。CI 的 delivery 作业会构建并启动真实镜像、运行浏览器主流程与备份恢复；以对应提交的绿色作业和 delivery-evidence 为验收依据。未验证生产容量。

## 数据库迁移

应用启动时由 Flyway 自动执行迁移，默认读取 `src/main/resources/db/migration`。当前 Flyway 基线是 V8，对应手工 V2–V7 完成后的完整结构：

- **空数据库**：Flyway 执行 V8，创建当前全部表和索引。只需先创建数据库，不要手工建表。
- **已有 V7 数据库**：Flyway 检测到非空 schema 且没有历史表，自动 baseline 到 8，不重复建表；随后 Hibernate 仍以 `validate` 校验结构。
- **早于 V7 的数据库**：不能直接 baseline 到 8。先停止写入并备份，按原顺序执行保留在 `src/main/resources/sql/upgrades/V2..V7` 的历史脚本，确认结构完整后再启动应用。
- **新变更**：后续只新增 `db/migration/V9__...sql`，不要修改已发布的迁移文件。Flyway 通过 `flyway_schema_history` 记录执行结果。

历史升级脚本仍保留用于审计和旧库补齐：V2 增加任务关联，V3 增加任务题目快照、幂等请求和尝试顺序，V4 增加内容寻址图片，V5 删除停用功能，V6 引入并行任务生命周期，V7 增加持久化任务名单。V2 若存在多条 `is_global=true` 任务，必须先人工确认当前任务并归档其余任务；MySQL DDL 可能分步提交，失败后检查已执行步骤再恢复，不能盲目重跑。

`schema_init.sql` 仅保留为手工查看结构的参考，不再作为生产启动步骤。`src/test/resources/mysql/schema-v1.sql` 含 `DROP DATABASE`，只用于 CI 或独立测试实例。

## 运行边界

登录限流、SSE 全局/用户连接名额和认证用户快照已由 Redis 跨实例协调；同一会话只允许一个活跃生成请求的所有权与取消路由仍在单个 JVM 内。扩容到多个实例前，仍需设计跨实例会话互斥及取消路由。任务归档保留数据；有关联教学任务的发布者账号不能直接删除，请改为停用。新建与升级库均通过外键保护任务关联；题库删除接口会拒绝有关联任务或作答的题目；用户删除仍遵循已有删除策略，归档承诺不是全系统软删除。

JWT 由持久化 token_version 校验；退出、改密、管理员改变角色或停用账号会撤销既有令牌。公开仅精确的登录/注册、健康等路径，生产文档默认关闭，指标要求教师令牌。登录限制通过 Redis 保持每账户/直连地址的固定窗口，反向代理部署必须配置可信代理策略，不能盲信转发头。

发布替换和归档锁定预期任务 ID；首次作答在用户行排他锁下验证幂等，并对任务行取共享锁，归档/替换使用排他锁，重试返回已保存结果。任务归档不接受新的原始作答，允许针对历史快照补练。部署验证与备份恢复命令见[交付验证](交付验证.md)。

## V7 名单口径

V7 新增 `task_recipients`，按任务和学生建立唯一约束。新任务发布时记录学生；注册、重新启用或转为学生的账号只加入尚未截止任务。已分配学生停用或转为教师后仍保留该作业历史。有关联名单的账号不可物理删除，请停用。发布、注册和管理员变更通过现有可用教师行锁串行处理名单与最后一位教师决策；逐题作答保留原来的用户行锁/任务共享锁。

升级前原始应参与名单无法完全还原：以迁移时启用学生和已知首次作答学生作为明确的迁移基线，记录 `source=MIGRATED`，教师详情显示局限；之后不再随账号变化漂移。首次应用 V7 前必须备份，停止写入并确认当前已完成 V6。
