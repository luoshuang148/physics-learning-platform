# 部署与数据库升级

## Docker 单机部署

复制 `.env.prod.example` 为 `.env`，填写数据库密码、随机 JWT 密钥、实际来源地址、模型密钥；首次教师按本地启动指南设置。执行：

```bash
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail=100 app
```

Compose 使用 MySQL 8.4、Java 21 和 Node 22 构建，前端打包进后端静态目录，访问 `http://服务器地址/api/v1/`。宿主机 `/data/mysql` 保存数据库，`/data/videos` 保存视频；启动前确认目录权限与磁盘空间。数据库端口只绑定本机。AI 可设置 `AI_ENABLED=false` 进行无模型演示。

首次成功启动教师账号后，关闭初始化、删除明文密码并重新创建 app 容器。配置 HTTPS、备份及真实监控后再用于外部用户。CI 的 delivery 作业会构建并启动真实镜像、运行浏览器主流程与备份恢复；以对应提交的绿色作业和 delivery-evidence 为验收依据。未验证生产容量。

## 从原始版本升级

应用不会自动迁移表结构。停止写入并备份数据库，确认实际版本后，在目标库执行一次：

```bash
mysqldump -u root -p --single-transaction zhixuewuli > backup-before-v2.sql
mysql -u root -p zhixuewuli < src/main/resources/sql/upgrades/V2__archive_teaching_events.sql
mysql -u root -p zhixuewuli < src/main/resources/sql/upgrades/V3__task_snapshots_and_attempts.sql
mysql -u root -p zhixuewuli < src/main/resources/sql/upgrades/V4__content_addressed_question_images.sql
mysql -u root -p zhixuewuli < src/main/resources/sql/upgrades/V5__remove_retired_learning_features.sql
mysql -u root -p zhixuewuli < src/main/resources/sql/upgrades/V6__parallel_assignments_lifecycle.sql
```

V2 新增活动任务唯一约束，以及答题、对话、报告的可空 `event_id`。V3 新增任务题目快照、幂等请求键、原始/补练字段、尝试顺序、报告依据及令牌版本。已在 V2 的库只执行 V3。已执行 V3 的库只执行 V4 和 V5。V4 新增 `question_images` 内容寻址表及 `answer_records.image_ref`，新作答不再重复写图片正文；旧完整 JSON 快照不批量回填、仍可直接读取，历史图片和解析不随题库修改变化。V6 为任务增加 `status/start_at/due_at` 并移除单活动槽限制，允许同一单班并行发布多个作业；旧 `is_global=true` 转为 `PUBLISHED`，其余转为 `ARCHIVED`。V5 删除已停用的 `answer_records.error_reason`、`questions.explanation_video_mapping` 以及 `videos`、`experiments` 表，执行前必须确认不再需要这些旧字段数据。升级脚本只执行一次，建议先备份。V3 还区分新增 UTC 时间与旧本地时间：新记录返回带 Z 的时间，旧记录不猜测偏移。旧 QIDS 的重复编号保留首次顺序，原始描述不改写；无效编号不生成虚假快照。V3 会让升级前的 JWT 失效，用户须重新登录。已有数据保留且不猜测历史所属任务。旧 QIDS 仅按升级时题库重建为 MIGRATED，已缺失题目标为 MISSING，不能宣称恢复了原始版本。

若旧库存在多条 `is_global=true` 的任务，先由运营确认当前任务，将其余任务设为归档，再执行升级。MySQL DDL 可能分步提交；该脚本只执行一次，失败后检查已执行步骤再恢复，不能盲目重跑。

`schema_init.sql` 用于空库，不作为增量迁移。`src/test/resources/mysql/schema-v1.sql` 含 `DROP DATABASE`，只用于 CI 或独立测试实例，不能运行于业务数据库。

## 运行边界

当前会话缓存和 SSE 连接限额保存在单个 JVM 中。扩容到多个实例前，需要设计共享限流、会话路由及取消语义。任务归档保留数据；有关联教学任务的发布者账号不能直接删除，请改为停用。新建与升级库均通过外键保护任务关联；题库删除接口会拒绝有关联任务或作答的题目；用户删除仍遵循已有删除策略，归档承诺不是全系统软删除。

JWT 由持久化 token_version 校验；退出、改密、管理员改变角色或停用账号会撤销既有令牌。公开仅精确的登录/注册、健康等路径，生产文档默认关闭，指标要求教师令牌。登录限制为单 JVM 的每账户/直连地址窗口，反向代理部署必须配置可信代理策略，不能盲信转发头。

发布替换和归档锁定预期任务 ID；首次作答在用户行排他锁下验证幂等，并对任务行取共享锁，归档/替换使用排他锁，重试返回已保存结果。任务归档不接受新的原始作答，允许针对历史快照补练。部署验证与备份恢复命令见[交付验证](交付验证.md)。
