# 部署与数据库升级

## Docker 单机部署

复制 `.env.prod.example` 为 `.env`，填写数据库密码、随机 JWT 密钥、实际来源地址、模型密钥；首次教师按本地启动指南设置。执行：

```bash
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail=100 app
```

Compose 使用 MySQL 8.4、Java 21 和 Node 22 构建，前端打包进后端静态目录，访问 `http://服务器地址/api/v1/`。宿主机 `/data/mysql` 保存数据库，`/data/videos` 保存视频；启动前确认目录权限与磁盘空间。数据库端口只绑定本机。AI 可设置 `AI_ENABLED=false` 进行无模型演示。

首次成功启动教师账号后，关闭初始化、删除明文密码并重新创建 app 容器。配置 HTTPS、备份及真实监控后再用于外部用户。这里提供单机部署配置，未验证容器镜像构建或生产容量；CI 验证的是 Maven、前端构建和 MySQL 数据路径。

## 从原始版本升级

应用不会自动迁移表结构。停止写入并备份数据库，确认实际版本后，在目标库执行一次：

```bash
mysqldump -u root -p --single-transaction zhixuewuli > backup-before-v2.sql
mysql -u root -p zhixuewuli < src/main/resources/sql/upgrades/V2__archive_teaching_events.sql
```

升级新增活动任务唯一约束，以及答题、对话、报告的可空 `event_id`。已有数据保留且不猜测历史所属任务。若旧库存在多条 `is_global=true` 的任务，先由运营确认当前任务，将其余任务设为归档，再执行升级。MySQL DDL 可能分步提交；该脚本只执行一次，失败后检查已执行步骤再恢复，不能盲目重跑。

`schema_init.sql` 用于空库，不作为增量迁移。`src/test/resources/mysql/schema-v1.sql` 含 `DROP DATABASE`，只用于 CI 或独立测试实例，不能运行于业务数据库。

## 运行边界

当前会话缓存和 SSE 连接限额保存在单个 JVM 中。扩容到多个实例前，需要设计共享限流、会话路由及取消语义。任务归档保留数据；有关联教学任务的发布者账号不能直接删除，请改为停用。新建与升级库均通过外键保护任务关联；普通学生或题目删除仍可能触发既有级联，不能把归档承诺理解为全系统软删除。

JWT 鉴权主要由 MVC 拦截器承担，教师操作另有服务层校验。上线前按部署范围控制文档、监控端点和来源策略。数据库唯一约束兜底防止两个活动任务，但任务切换期间的并发写入仍需按业务要求补充一致性策略。
