# 查询与资源验证

## 已测的 SQL 改进

用例：`src/test/java/com/zhixuewuli/repository/AnswerRecordQueryRegressionTest.java`。

- 环境：Java 21、Spring Data JPA / Hibernate、H2 测试库。
- 数据：1 个教师、1 个学生、25 条答题，每条关联不同的题目。
- 测量前执行 flush / clear，清空 Hibernate 统计，避免一级缓存掩盖 N+1。
- 调用旧版教师全量列表方法，统计 `prepareStatementCount`。
- 原始实现为 27 条：1 条身份查询、1 条答题列表查询、25 条题目查询。
- 关联预取后的实现为 2 条：身份查询和关联列表查询。

复现：

```bash
./mvnw -B test -Dtest=AnswerRecordQueryRegressionTest
```

新教师页面调用 `/api/v1/answer-records/teacher/page?page=1&size=20`。服务端限制 size 在 1–100，按答题时间、ID 倒序，支持 `wrongOnly` 和 `studentName`。DTO 投影只取列表需要的字段，不选择图片正文；分页有内容查询和总数查询，不能把旧列表的“2 条”直接套用于每次分页请求。正确性和权限分别由仓储/服务/控制器测试覆盖。

学生历史和错题列表使用 `/answer-records/student/history`、`/answer-records/student/practice-review/page` 及教师端 `/answer-records/user/{id}/history`。轻量行不加载图片和完整解析，详情通过 `/answer-records/{recordId}` 按权限读取。旧全量入口仍可用，但超过 100 条会明确返回参数错误，不截断。最近会话按 `answeredAt DESC, attemptOrder DESC` 选取，数据库只读取第一条会话 ID。

## 流式资源回归

本地 HTTP 测试服务器发送一条有效的模型 SSE 内容，然后保持连接不再输出。测试取消请求后必须在超时预算内结束读取，验证真正调用 `OkHttp Call.cancel()`，不依赖真实模型。另有同会话重复请求、执行队列拒绝和清理路径测试。

这些测试证明取消与资源释放行为，不代表能承受某个 QPS，也不证明外部模型首字延迟。线程池、连接上限和缓存上限是单 JVM 内的保护，不是分布式限流。

## 本轮 MySQL HTTP 实测

本地 Darwin arm64、8 逻辑核，Java 21（该次 Jar 设置 `-Xmx512m`）、MySQL 8.0.46，独立临时数据目录，AI 关闭。100 个合成学生、50 道题、5000 条原始作答，每条作答保存 1KB 合成图片快照。更新统计信息并预热后，两接口交替执行共 400 次请求、并发 8，各 200 个样本；测量期间不同时运行备份或其他验证任务。

| 场景 | 成功请求 | 总吞吐（两接口混合） | 分页 P50 / P95 | 任务统计 P50 / P95 |
| --- | --- | --- | --- | --- |
| 原索引 | 400/400 | 53.65 次/秒 | 128.17 / 185.38 ms | 157.96 / 217.19 ms |
| 增加任务统计覆盖索引 | 400/400 | 84.54 次/秒 | 100.15 / 146.13 ms | 77.54 / 140.73 ms |

`idx_event_summary(event_id,practice,user_id,question_id,correct,attempt_order)` 让任务聚合读取窄索引，避开大快照行。MySQL `EXPLAIN ANALYZE` 确认总量统计由索引回表改为 covering index lookup；单次 SQL 观察约 7.56 ms 与 2.92 ms。新增索引会增加写入与磁盘成本。原始 [基线 JSON](verification/2026-10-18-http-baseline.json)、[覆盖索引 JSON](verification/2026-10-18-http-covered.json) 可核对。

这是同一台机器按顺序进行的两次短实验，仍受 JVM、数据库缓存及系统噪声影响，不能单凭它声称通用提升百分比或生产容量。曾与备份重叠的探索性样本未作为对比依据。CI 会重新生成本次提交的测量 artifact；没有设置不稳定的跨机器毫秒门槛。

有界恢复回归还验证了 40 条持久化历史只加载最近 3 条实体，同时保留 400 token 和下一序号 41；不是只在内存中裁剪。复现说明见[交付验证](交付验证.md)。

## 任务提交锁实测

独立 MySQL 8.0.46、40 名合成学生、5 轮任务、200 次首次作答：旧任务行排他锁 P95 241.94 ms、吞吐 158.52 次/秒；共享锁 P95 158.20 ms、吞吐 236.49 次/秒，200/200 成功。机器、数据、一致性检查和适用范围见[任务提交锁竞争验证](锁竞争验证.md)，原始 JSON 在同目录 `verification/`。这是单机短实验，不能作为生产容量承诺。

## 扩展压测方法

学生学情分析页现通过用户列表和 `/answer-records/teacher/student-stats` 两次请求加载列表与计数，替代为每位学生下载全部作答和错题明细的 `2N` 次请求。选中学生后只获取一次作答明细，错题视图从该结果筛选；切换学生时忽略旧请求的成功及失败响应。统计包括首次与补练尝试，未作答学生显示零，已停用学生保留历史统计。

`StudentAnswerStatsControllerTest` 验证统计不加载答题和题目实体；`AnswerRecordSessionQueryTest` 在冷上下文下验证学生会话归属检查与响应只执行一次记录查询（重构前为两次）。浏览器验证见 `frontend/e2e/student-analysis.spec.ts`，使用受控 HTTP 响应，不依赖真实模型。

使用独立 MySQL 测试实例及虚拟账号，准备不同规模的答题和题目，先执行一次预热，再对已登录教师的分页 GET 接口进行并发请求。记录数据量、机器 CPU/内存、JDK/MySQL 版本、并发数、成功率、吞吐量、P50/P95/P99、服务端 CPU/堆内存及数据库慢查询。

分页测试应覆盖有无姓名筛选、前页与深页。姓名包含匹配并不保证使用普通索引；深 OFFSET 分页也可能变慢，应通过 EXPLAIN 和实测决定是否增加组合索引或改成游标分页。

真实模型测试应独立进行并限制费用，区分客户端连接数、服务端队列等待、上游首字延迟和总生成时间。本文没有生产容量、真实模型并发或端到端延迟结果；简历不能填入未测的数值。
